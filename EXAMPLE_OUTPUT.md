# Weekly Team Status Report - SOP

## Purpose
This process ensures consistent, timely communication with stakeholders about product team progress, blockers, and priorities. The weekly status report provides executives and cross-functional leaders with visibility into completed work, ongoing initiatives, and potential risks.

## Owner
**Primary:** Team Lead or Product Manager  
**Backup:** Senior Product Team Member

## Prerequisites
- [ ] Access to Google Drive team folder
- [ ] Status report template (located in Google Drive)
- [ ] Access to stakeholder distribution list
- [ ] Calendar access to schedule team check-ins
- [ ] Previous week's status report for reference

## Steps

### 1. Initiate the Process
**When:** Every Monday at 9:00 AM  
**Action:** Open the status report template from Google Drive (Team Folder)  
**Role:** Team Lead / Product Manager  
**Tools:** Google Drive  
**Time:** 2 minutes

**Details:**
- Navigate to team folder in Google Drive
- Duplicate the template for the current week
- Rename with format: "Status Report - [Date]"

---

### 2. Review Previous Week's Action Items
**Action:** Analyze last week's report to identify completed vs. pending items  
**Role:** Team Lead / Product Manager  
**Tools:** Previous week's status report  
**Time:** 5 minutes

**Details:**
- Open previous week's report
- Check each action item against actual completions
- Note any slipped deadlines or incomplete tasks
- Prepare to address gaps in stakeholder communication

**Why This Matters:** Tracking completion rates builds credibility and helps identify patterns in estimation or resourcing issues.

---

### 3. Schedule Team Check-ins
**Action:** Book 10-minute 1-on-1 meetings with each team member  
**Role:** Team Lead / Product Manager  
**Tools:** Calendar (Google Calendar, Outlook, etc.)  
**Time:** 5 minutes to schedule, 50-60 minutes for meetings

**Details:**
- Schedule with all 5 team members (adjust for your team size)
- Block consecutive time slots to complete within one hour
- Send calendar invites with "Weekly Status Check" title
- Include agenda: Completions, Current Work, Blockers

**Tips:** 
- Back-to-back scheduling is efficient but allow 5-min buffer between meetings
- Can be done via Slack huddle, Zoom, or in-person

---

### 4. Conduct Team Check-ins
**Action:** Meet with each team member and gather updates  
**Role:** Team Lead / Product Manager  
**Tools:** Meeting platform + note-taking tool  
**Time:** 10 minutes per person (50-60 minutes total)

**Three Key Questions:**
1. **What did you complete last week?** (Look for specific deliverables, not vague progress statements)
2. **What are you working on this week?** (Understand priorities and time allocation)
3. **Are there any blockers?** (Identify issues that need escalation or support)

**Notes Best Practices:**
- Document specific deliverables, not generic statements
- Example GOOD: "Completed API integration for user authentication"
- Example BAD: "Made progress on authentication"
- Note any dependencies between team members
- Flag items that need stakeholder attention

---

### 5. Compile Updates into Template
**Action:** Organize all gathered information into the status report format  
**Role:** Team Lead / Product Manager  
**Tools:** Google Docs, status report template  
**Time:** 15-20 minutes

**Structure:**
- **By Person:** List each team member with their updates
- **By Project:** Group related work items together
- Ensure each update is:
  - ✅ Clear and specific
  - ✅ Results-oriented
  - ✅ Easy for non-technical stakeholders to understand

**Organization Tips:**
- Use consistent formatting (bullet points, headers)
- Group related projects together
- Highlight key accomplishments in bold

---

### 6. Add New Action Items
**Action:** Document new action items from check-ins and other meetings  
**Role:** Team Lead / Product Manager  
**Tools:** Status report template  
**Time:** 10 minutes

**Required for Each Action Item:**
- [ ] Clear description of the task
- [ ] Owner (specific person assigned)
- [ ] Due date
- [ ] Context (why it matters)

**Format Example:**
```
Action Item: Complete API documentation for v2 endpoints
Owner: Sarah Chen
Due Date: Friday, Nov 3
Context: Needed for external developer onboarding
```

---

### 7. Highlight Blockers and Risks
**Action:** Identify and document any issues that could impact timeline or deliverables  
**Role:** Team Lead / Product Manager  
**Tools:** Status report template  
**Time:** 10 minutes

**Use Status Indicators:**
- 🟢 **Green:** On track, no issues
- 🟡 **Yellow:** Minor concerns, monitoring closely
- 🔴 **Red:** Significant blocker, requires immediate attention

**For Each Blocker Document:**
- What is blocked
- Why it's blocked
- Impact on timeline/deliverables
- Proposed resolution or escalation needed

**Critical:** Don't sugarcoat issues. Stakeholders need accurate information to make decisions.

---

### 8. List Next Week's Priorities
**Action:** Outline the top 3-5 initiatives for the upcoming week  
**Role:** Team Lead / Product Manager  
**Tools:** Status report template  
**Time:** 5 minutes

**Guidelines:**
- Focus on the most important initiatives (3-5 max)
- Include projects that stakeholders care about
- Provide context for new initiatives
- Link to longer-term roadmap items when relevant

**Example Format:**
```
Next Week's Priorities:
1. Complete user authentication API integration (on roadmap for Q4)
2. Begin user testing for new dashboard design (15 participants)
3. Resolve production bug affecting 5% of users (high priority)
4. Finalize scope for v2.0 release (stakeholder review needed)
```

---

### 9. Check with Engineering Lead (Critical!)
**Action:** Verify any infrastructure issues or technical blockers  
**Role:** Team Lead / Product Manager  
**Tools:** Slack, email, or quick call  
**Time:** 5 minutes

**Ask About:**
- Ongoing infrastructure issues
- Planned maintenance or downtime
- Performance concerns
- Security incidents or vulnerabilities
- Upcoming technical debt work

**⚠️ Common Mistake:** Forgetting this step. Infrastructure issues may not surface in individual check-ins but are critical for stakeholder awareness.

- [ ] All sections completed
- [ ] Status indicators applied correctly
- [ ] Action items have owners and dates
- [ ] Executive-appropriate language (clear, concise, professional)

**Tip:** Read it as if you're a stakeholder who knows nothing about the details. Does it make sense?

## Success Criteria

The status report is successful when:
- [ ] Distributed to all stakeholders by Monday 2:00 PM deadline
- [ ] All sections are complete (no "TBD" or missing information)
- [ ] Blockers are clearly identified with red/yellow/green indicators
- [ ] Every action item has an owner and due date
- [ ] Updates are specific and results-oriented (not vague)
- [ ] Engineering lead has confirmed no missing infrastructure issues
- [ ] Document is proofread with no grammatical errors
- [ ] Copy archived in the correct folder
- [ ] Stakeholders acknowledge receipt (optional: request confirmation)

## Common Pitfalls & Troubleshooting

### ❌ **Issue:** Forgot to check with engineering lead about infrastructure issues
**→ Solution:** Add a recurring reminder in your calendar for Monday 11am. Make this a non-negotiable step.

---

### ❌ **Issue:** Team members give vague updates like "made progress"
**→ Solution:** During check-ins, probe deeper. Ask: "What specific deliverable did you complete?" or "What can you demo right now?"

---

### ❌ **Issue:** Report is late (sent after 2pm deadline)
**→ Solution:** 
- Start earlier (8am instead of 9am)
- Use a template with pre-filled sections to save time
- Delegate some compilation work to a senior team member

---

### ❌ **Issue:** Stakeholders ask clarifying questions about unclear updates
**→ Solution:** Before sending, read each update from the perspective of someone outside the team. Add context for any technical terms or project codenames.

---

### ❌ **Issue:** Blockers are downplayed or hidden to "look good"
**→ Solution:** Remember: Hiding problems makes them worse. Stakeholders want transparency to help solve issues, not to assign blame.

---

### ❌ **Issue:** Action items from previous weeks are forgotten or lost
**→ Solution:** Maintain a running action items tracker (separate from the weekly report). Review this tracker at the start of each report cycle.
